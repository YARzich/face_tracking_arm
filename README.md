# face_tracking_arm

Это pet-проект с роборукой UFACTORY xArm6 и камерой над экраном: он обнаруживает
лица, оценивает их положение в 3D и направляет экран к ближайшему устойчиво
видимому лицу. После потери лица контроллер может вернуться к настроенной позе
отдыха или искать новую цель; при ошибке входных данных он останавливает слежение.
Проект использует ROS 2 Jazzy, Gazebo Harmonic для тестовых сцен и Docker-команды
для запуска реальной руки.

## Реальная рука

Сначала прочитайте [руководство по запуску xArm6](docs/hardware.md). Оно описывает
Docker, камеру, конфигурацию и проверки перед движением.

Краткий порядок запуска:

1. Подготовьте образ: `./run prepare`.
2. Укажите руку, камеру и геометрию в `config/hardware.yaml`.
3. Проверьте изображение: `./run cpu --camera-only --show-image`.
4. Убедитесь, что рука готова к движению в UFACTORY Studio.
5. Остановите просмотр сочетанием Ctrl+C. Затем запустите `./run cpu`.

**Рука может начать двигаться сразу после запуска.** Для стереокамеры используйте
`./run stereo`, для RealSense RGB-D — `./run rgbd`. Подробные команды и варианты
сглаживания точки лица описаны в [руководстве по оборудованию](docs/hardware.md).
Параметры камер и оси координат описаны в [руководстве по камерам](docs/cameras.md).

Для разового выбора фильтра добавьте к `./run cpu`, `./run stereo` или
`./run rgbd` один аргумент: `--point-filter off`, `--point-filter one_euro` или
`--point-filter kalman`. Для настройки крепления и камеры см.
[руководство по креплению](docs/mount_setup.md).

## Как работает управление

Узел обработки изображения находит рамку лица и оценивает точку в 3D.
Обычная камера оценивает расстояние по размеру рамки. Стереокамера использует
разницу между двумя изображениями. Точка хранит время кадра и систему координат.
ROS TF преобразует точку к системе робота.

В режиме FACE контроллер стремится направить экран на свежую цель.
Ограничения суставов, скорости, столкновений и качества входных данных могут
ограничить движение. Если J1 достигает рабочего края, контроллер может продолжить
поворот через J4. Отдельный компактный маршрут разрешён только при исчерпании
полезного поворота пары J1/J4 в нужном направлении. Одна ошибка наведения или
ограничение другого сустава этот маршрут не запускают. Подробности см.
[описание архитектуры](docs/architecture.md).

## Ограничения

- Расстояние по одной камере приблизительное. На оценку влияют размер и поворот лица.
- Стерео требует калибровки и кадров, снятых почти одновременно.
- Компактный маршрут предназначен для исчерпания поворота J1/J4. Он не восстанавливает
  движение при ограничении любого другого сустава.
- Геометрия стола и крепления задаётся вручную. Камера не строит карту препятствий.
- Лицо в кадре не означает, что контроллер всегда может навести экран на лицо.
- Вариант оценки глубины на GPU экспериментальный. Не используйте его как основной
  без отдельной проверки точности.

[Сборка и проверки одного пакета](CONTRIBUTING.md). GitHub Actions собирает
`face_tracking_arm` и запускает пакетные тесты на ROS 2 Jazzy. Это не проверка
