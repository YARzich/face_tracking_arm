# Слежение за лицом в Gazebo

Эти сценарии проверяют руку, камеры и детектор в Gazebo Harmonic. YuNet находит
лицо на изображении. Обработчик оценивает его положение в метрах. Рука
направляет монитор к измеренной точке.

Сцена использует изображение человека, но удаляет его физические столкновения.
Тест проверяет зрение и движение руки. Он не проверяет обнаружение человека
как препятствия. Столкновения руки со столом и самой рукой остаются включены.

Для всех сценариев сначала подготовьте модель человека и Python-окружение
по [инструкции 2D-теста](face_detection_test.md#подготовка). Затем выполните
[сборку пакета](../CONTRIBUTING.md).

## Запуск

Откройте терминал и запустите обычную RGB-камеру:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 launch face_tracking_arm tracking_cpu.launch.py
```

Для стереокамеры остановите первый запуск клавишами Ctrl+C и выполните:

```bash
ros2 launch face_tracking_arm tracking_stereo.launch.py
```

Открываются Gazebo и RViz. RViz показывает изображение камеры, рамки лиц и
3D-точку. Завершите запуск клавишами Ctrl+C. Аргумент `headless:=true` отключает
оба окна. Аргумент `show_image:=false` отключает только RViz.

По умолчанию запускается сценарий `appearances`: человек появляется перед рукой.
Выберите другой сценарий аргументом `scenario`:

| Значение | Что проверяет | Поза и поведение без лица |
|---|---|---|
| `appearances` | Появления и короткие движения одного или двух людей | `rest`, возврат в `rest` |
| `stress` | Широкое движение, разные высоты и потерю цели | `zero`, поиск |
| `stress_fast` | Быстрый поворот, приближение и выбор среди трёх лиц | `rest`, поиск |
| `stress_close` | Близкий подход, боковой проход и отход | `rest`, поиск |

Например, запустите быстрый сценарий один раз:

```bash
ros2 launch face_tracking_arm tracking_cpu.launch.py \
  scenario:=stress_fast cycles:=1
```

Для стерео замените `tracking_cpu.launch.py` на `tracking_stereo.launch.py`.
Выбирайте одну launch-команду за раз. Значение `cycles:=0` повторяет сценарий;
`cycles:=1` выполняет один цикл.

## Быстрые движения и фоновые лица

Сценарий `stress_fast` длится 96 с. Один человек движется. Два других остаются
на месте. На дальней остановке контроллер должен выбрать ближайшее видимое лицо,
затем вернуться к основному человеку.

| Время | Действие |
|---|---|
| 0–20 с | Короткие движения в стороны и по высоте |
| 20–34 с | Подход до радиуса 1.4 м |
| 34–56 с | Отход до радиуса 3.6 м и остановка |
| 56–76 с | Возврат ближе к фоновым лицам |
| 76–96 с | Возврат в исходную точку |

Радиус измеряется от основания руки до начала модели человека. Скорость модели
на быстрых участках достигает около 1.25 м/с. Движение цели намеренно может
быть быстрее руки.

Пример со стереокамерой:

```bash
ros2 launch face_tracking_arm tracking_stereo.launch.py \
  scenario:=stress_fast cycles:=1
```

Смотрите на выбранную рамку и поле `selected_track_id` в
`/face_test/depth_status`. Номер дорожки не является личностью. Приблизительная
глубина обычной камеры может дать ошибочный порядок ближних лиц.

## Очень близкий человек

Сценарий `stress_close` длится 120 с. Он проверяет близкий подход, боковой
проход, смену высоты и отход. Запустите его с обычной камерой:

```bash
ros2 launch face_tracking_arm tracking_cpu.launch.py \
  scenario:=stress_close cycles:=1
```

Для стерео используйте `tracking_stereo.launch.py`. Можно сравнить сглаживание:

```bash
ros2 launch face_tracking_arm tracking_stereo.launch.py \
  scenario:=stress_close cycles:=1 \
  point_smoothing:=true point_smoothing_method:=kalman
```

| Время | Действие |
|---|---|
| 0–22 с | Покой и подход от радиуса 2.1 м до 1.0 м |
| 22–32 с | Покой, затем близкий подход до 0.75 м |
| 32–42 с | Близкая остановка |
| 42–48 с | Проход вбок: от −45° до +45° и возврат |
| 48–66 с | Смена высоты лица с 1.55 до 1.70 и 1.40 м |
| 66–82 с | Низкая близкая остановка |
| 82–108 с | Отход и возврат к начальной точке |
| 108–120 с | Финальная остановка |

Радиус в таблице измерен до начала модели человека. Лицо выступает примерно
на 0.20–0.22 м к роботу. Параметр `minimum_face_distance_m` задаёт желаемое
расстояние от лица до центра монитора (его frame); в симуляции по умолчанию
это 0.40 м. Система ограничивает требуемое смещение монитора безопасным
радиусом досягаемости. Поэтому параметр задаёт цель, а не гарантированный
зазор до поверхности монитора. Кинематика и измерение глубины также могут
помешать достичь этой цели.

По изображению проверьте, остаётся ли лицо видимым во время бокового прохода.
Если оно выходит за край кадра, это потеря входной цели, а не доказательство
ошибки распознавания личности: проект не распознаёт личности.

## Сглаживание точки лица

В симуляции сглаживание выключено по умолчанию. Чтобы включить фильтр Калмана:

```bash
ros2 launch face_tracking_arm tracking_cpu.launch.py \
  scenario:=stress_close cycles:=1 \
  point_smoothing:=true point_smoothing_method:=kalman
```

Метод `one_euro` доступен вместо `kalman`. Он выбран по умолчанию, если
сглаживание включено. При выключенном `point_smoothing` параметр метода
не действует.

| Параметр | По умолчанию | Единица или смысл |
|---|---:|---|
| `point_smoothing` | `false` | Включить фильтр |
| `point_smoothing_method` | `one_euro` | `one_euro` или `kalman` |
| `point_smoothing_min_cutoff_hz` | 1.5 | Частота среза One Euro, Гц |
| `point_smoothing_beta` | 32.0 | Реакция One Euro на скорость, 1/м |
| `point_kalman_measurement_std_m` | 0.02 | Ожидаемый шум измерения, м |
| `point_kalman_acceleration_std_mps2` | 1.5 | Ожидаемое изменение скорости, м/с² |

Фильтр уменьшает шум, но добавляет задержку. Он сбрасывается после смены лица
или длинного перерыва. Он не выдаёт новую точку после потери лица. Калман не
исправляет систематическую ошибку глубины обычной камеры.

В `/face_test/depth_status` поля `raw_x_m`, `raw_y_m`, `raw_z_m` показывают
исходную оценку. Поля `x_m`, `y_m`, `z_m` показывают результат фильтра.
`point_smoothing_correction_m` показывает разницу между точками.

## Сложный маршрут и стартовые позы

Сценарий `stress` длится 134 с и начинается из `zero`. Он меняет расстояние,
высоту и направление, теряет лицо и снова показывает его. Запустите его:

```bash
ros2 launch face_tracking_arm tracking_cpu.launch.py \
  scenario:=stress cycles:=1
```

Маршрут включает подход, боковую дугу, смену направления, остановку, потерю
лица и повторное обнаружение. Используйте `cycles:=1` для одного прохода.
Сценарий начинает движение по расписанию после первых суставных данных. Он не
ждёт, пока рука найдёт лицо.

| Поза | Значение |
|---|---|
| `rest` | Стандартная поза из конфигурации |
| `zero` | Все шесть углов равны нулю |
| `folded` | Сложенная поза xArm6 |
| `joint1_limit` | J1 около +359.9° |
| `incident` | Проверочная поза только для Lite6 |

Пример запуска сложенной xArm6:

```bash
ros2 launch face_tracking_arm tracking_cpu.launch.py \
  scenario:=stress cycles:=1 start_pose:=folded
```

`incident` проверяет блокировку пересекающейся позы Lite6. Поза и углы J1–J6
описаны в [руководстве по симуляции](simulation.md#начальная-поза). Можно
передать свой файл через `initial_positions_file`; задайте в YAML ровно шесть
углов в радианах.

Путь компактной перестройки предназначен только для восстановления поворота
пары J1/J4, когда полезный поворот этой пары исчерпан. Обычное отставание,
скачок цели или ограничение другого сустава само по себе не является причиной.
Проверьте фактические суставы, положение и ориентацию монитора, а также
диагностику. Переход имени фазы сам по себе не подтверждает успешный манёвр.
Этот тест не является общей проверкой безопасности оборудования.

## Последовательность целей

Сценарий `appearances` использует одного человека по умолчанию. Параметр
`people_count` допускает 1 или 2 для этого сценария. Человек появляется на
12 с, затем скрывается. Следующее появление ждёт возврата руки или готовности
поиска. Координаты задаёт `config/face_appearances.yaml`.

Управляйте ожиданием через `idle_behavior`:

| Значение | Действие после потери лица |
|---|---|
| `rest` | Возврат в исходную позу |
| `search_sweep` | Компактный переход, затем широкий поиск |
| `search_local_then_sweep` | Сначала локальный поиск, затем широкий |

`stress_fast` требует `people_count:=3`. `stress` и `stress_close` требуют
`people_count:=1`. Launch задаёт эти значения автоматически; не меняйте
их вручную без необходимости.

Контроллер обычно использует последнюю измеренную точку до 0.5 с. Если потоки
исправны, краткий прогноз может длиться до 0.8 с от исходной метки кадра.
После этого рука переходит в HOLD. Ошибка обязательного потока прекращает
прогноз сразу. Возврат или поиск начинается после задержки, заданной параметром
`return_to_rest_delay_sec`; по умолчанию это 2 с. Прогноз не продлевается этой
задержкой.

При нескольких лицах контроллер выбирает ближайшее лицо с пригодной глубиной.
Сначала новое лицо должно быть видно в нескольких кадрах. Затем оно должно
быть заметно ближе в течение заданного времени. Это сопоставление положения,
а не распознавание личности. Перекрытие лиц может изменить выбор.

## Камеры и данные

Сценарии используют камеры на мониторе. По умолчанию обычная RGB-камера имеет
размер 1280×720, стерео — 640×360. Частота равна 30 Гц, горизонтальный угол
обзора около 82°. Стереобаза по умолчанию равна 0.08 м.

Аргументы `camera_width`, `camera_height`, `camera_rate` и
`camera_horizontal_fov` меняют камеру в симуляции. `baseline` задаёт расстояние
между стереокамерами. Эти настройки не меняют параметры реальной камеры.

Обычная камера оценивает расстояние по ширине лица и принятому значению
`face_width_m`. Это приблизительный расчёт. Стерео оценивает глубину по разнице
изображений; оно не использует глубину Gazebo. Для сравнения методов откройте
[тесты глубины](face_depth_tests.md).

Основные выходы:

| Топик | Данные |
|---|---|
| `/face/center` | Выбранная точка лица в метрах |
| `/face_test/debug_image` | Кадр с рамками лиц |
| `/face_test/depth_status` | Оценка глубины, выбранное лицо и состояние потоков |
| `/face_test/scenario` | Фаза и таймер сценария |
| `/tracking/diagnostics` | Режим и причина состояния слежения |
| `/servo_node/diagnostics` | Диагностика движения |

Координаты камеры используют optical frame: X вправо, Y вниз, Z вперёд.
Точка сохраняет время изображения. Для текущего положения и наведения экрана
проверяйте TF с теми же метками времени.

## Ограничения

Номер выбранной дорожки не является личностью. Обычная камера не измеряет
точную глубину. Стерео требует правильной калибровки, синхронизации и
выравнивания кадров. Манекен удалён из физической сцены, поэтому сценарий
не проверяет столкновение руки с человеком.

Для настоящей RGB-D камеры используйте [руководство по оборудованию](hardware.md).
Там настроены отдельные топики, выравнивание глубины и ограничения свежести.
