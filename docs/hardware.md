# Запуск xArm6 через Docker

Нужен Linux с обычным локальным Docker Engine; Docker Desktop и rootless-режим
не поддерживаются. ROS и Python-пакеты на компьютере устанавливать не нужно.
Все команды выполняйте в терминале из папки `face_tracking_arm`.

## 1. Подготовить окружение

Если Docker ещё не установлен, на Ubuntu выполните:

```bash
sudo apt update
sudo apt install --no-remove docker.io
sudo systemctl start docker
```

Подготовьте образ проекта:

```bash
./run prepare
```

При необходимости введите пароль sudo. Готовый совместимый образ загрузится
из `dist`, если он там есть; иначе соберётся автоматически. Первая сборка
требует интернета. Настройка робота и камеры повторной сборки не требует.
Если команда сообщает об устаревшем образе, выполните `./run build` один раз
или получите готовый образ для этой версии проекта.

## 2. Указать своё оборудование

```bash
nano config/hardware.yaml
```

| Поле | Что указать |
|---|---|
| `robot.model` | `xarm6`; для Lite 6 — `lite6` и подходящие ей позы/нагрузка |
| `robot.ip` | IP руки из UFACTORY Studio |
| `robot.base_xyz_m` | Положение основания; Z — высота установки в метрах |
| `table` | Размеры и положение столешницы |
| `monitor`, `camera_mount` | Измеренные размеры, масса с креплениями и положение экрана/камеры |
| `tracking.idle_behavior` | Для первого запуска оставить `rest` |
| `motion.speed_scale` | Для первого запуска оставить `0.25` |
| `point_filter` | Сглаживание точки лица; в шаблоне включён Калман с отдельными настройками CPU/стерео |

Размеры `_m` — **метры**: `0.10` = 10 см. Масса `_kg` — килограммы.
Размеры экрана P16 в примере приблизительные: замените их измеренными.
`robot.model_num` оставьте `0`: при подключении вариант xArm6 определяется по руке.
`perception.python_executable` и `model_dir` для стандартного запуска менять не нужно.

Редактируйте файл на компьютере, не внутри контейнера. Настройки применяются
при следующем запуске. Путь к другому файлу указывайте во всех командах камеры
и слежения:

```bash
./run cpu --config /путь/hardware.yaml --camera-only --show-image
```

Пути к калибровке и моделям относятся к файлам **на компьютере**.
Относительные пути считаются от папки выбранного `hardware.yaml`.

### Если геометрия стола или экрана не нужна

В существующих секциях измените только размеры; остальные поля сохраните:

```yaml
table:
  shape: cylinder
  dimensions_m: [0, 0]
monitor:
  size_m: [0, 0, 0]
```

Для прямоугольного стола (`shape: box`) нужны три нуля: `[0, 0, 0]`.
Стол и экран можно отключать независимо. Все размеры должны быть либо
положительными, либо нулевыми; смешанный вариант вроде `[0, 0.3, 0.2]` — ошибка.

Нули убирают объект из модели и проверки столкновений. **Стол или экран с такими
настройками больше не учитывается при движении.** Камера, положение основания
и крепления сохраняются; их координаты указывайте по фактической установке.
Если экрана физически нет, при нулевых размерах можно также указать
`monitor.mass_kg: 0`. Положительная указанная масса продолжает учитываться
в проверке нагрузки.

## 3. Подготовить камеру

Выберите одну из двух веток ниже.

### Logitech BRIO C1000e / другая USB-камера

```bash
./run devices
```

В `mono_cpu.left.device` укажите путь камеры, лучше `/dev/v4l/by-id/...`.
Оставьте `source: usb`, `rectification: raw`. Начните с 640×480, 30 FPS.

Для BRIO в шаблоне задан `control_values: {logitech_brio_fov: '90', zoom_absolute: minimum}`:
программа запрашивает режим обзора 90° по диагонали и минимальный цифровой зум,
затем читает настройки обратно. Если конкретное USB-устройство не поддерживает
их, запуск остановится с названием настройки. Для другой камеры удалите эти
две записи или замените их настройками, которые она поддерживает. [Подробнее о настройках камеры](cameras.md).

Если калибровка есть, впишите её YAML в `mono_cpu.left.calibration_file`.
Иначе оставьте поле пустым и выполните:

```bash
./run calibrate cpu --size 8x6 --square 0.025
```

Нужна плоская шахматная доска. `8x6` — **внутренние углы**, `0.025` — сторона
клетки **в метрах**; подставьте размеры своей доски. Покажите её под разными
углами и у краёв кадра. Нажмите **CALIBRATE → SAVE**, затем Ctrl+C.
Файл появится в `config/calibration/mono_cpu/left.yaml` и будет использован автоматически.
При своём `--config` папка `calibration/mono_cpu` создаётся рядом с выбранным YAML;
для калибровки передайте тот же `--config`. Чтобы использовать этот результат,
оставьте `calibration_file: ''`: непустой путь выбирает указанный вами файл.
После смены разрешения, FOV, зума или фокуса выполните калибровку заново.
Если USB-камера требует другого способа чтения, задайте
`driver_parameters.io_method: read` или `userptr`; обычное значение — `mmap`.

### Стереокамера

1. Запустите ROS-драйвер камеры с `ROS_DOMAIN_ID=71`, отдельно или в контейнере
   производителя с сетью `host`. Нужны левое/правое изображения и их `CameraInfo`
   с калибровкой.
2. В `stereo` оставьте `source: ros`. Заполните `image_topic`, `info_topic`,
   `frame_id` для `left` и `right` по данным драйвера.
3. Выберите `rectification: rectified`, если изображения уже выровнены.
   `baseline_m: 0.0` берёт расстояние между объективами из калибровки;
   иначе впишите реальную базу в метрах. Начните с `sync_slop_sec: 0.005`.
4. Укажите положение и поворот объективов: `optical_xyz_m`, `optical_rpy_deg`.
   [Как согласовать TF с драйвером камеры](cameras.md#камера-со-своим-ros-драйвером).

Для двух USB-камер выберите `source: usb`, `rectification: raw`, укажите два разных
`device`, оставьте `calibration_file` пустыми и выполните:

```bash
./run calibrate stereo --size 8x6 --square 0.025
```

После **CALIBRATE → SAVE** и Ctrl+C калибровка появится в `config/calibration/stereo/`.
При своём `--config` папка создаётся рядом с выбранным YAML.
Оставьте оба `calibration_file: ''`, чтобы использовать этот результат.
Для движущихся лиц нужна синхронная съёмка обеими камерами.
При смене разрешения или стереобазы доступны `stereo.num_disparities` и
`stereo.block_size`: [как настроить расчёт глубины](cameras.md#диапазон-стереоглубины).

## 4. Проверить изображение и обнаружение лица

Проверка только камеры, без подключения к руке:

```bash
./run cpu --camera-only --show-image
```

Для стерео замените `cpu` на `stereo`. Покажите лицо: должна появиться рамка,
а в терминале — `OK` и координаты. Остановите проверку через Ctrl+C.

Красная точка и рамка в окне — исходный результат детектора. Калман сглаживает
3D-точку для управления, поэтому красная точка может немного дрожать и при включённом фильтре.

## 5. Проверить руку в UFACTORY Studio

1. Подключите руку по Ethernet. Компьютер и рука должны иметь разные IP одной подсети.
2. Задайте в Studio массу экрана, камеры, креплений и их общий центр тяжести.
   Значения массы в `hardware.yaml` не заменяют эту настройку. Общая нагрузка
   xArm6 — до 5 кг.
3. Устраните ошибки и проверьте готовность руки в Studio.
4. На малой скорости проверьте позы `motion.rest_joints_deg` и
   `motion.search_joints_deg` с установленным экраном. Значения — шесть углов
   в градусах по порядку суставов 1–6.

## 6. Запустить слежение

Закрепите основание, освободите место для движения и держите аварийную кнопку
доступной. **Следующая команда включает управление и может сразу двигать руку.**

```bash
./run cpu
```

Или со стереокамерой:

```bash
./run stereo
```

Перед включением управления программа считывает модель, версию, текущие углы
и ограничения Reduced Mode. Несоответствие модели, недопустимая поза или скорость
останавливает запуск; ограничения не повышаются автоматически.
Затем драйвер проверяет готовность, включает приводы и переводит руку в режим
слежения. Восстановление слежения во время работы не перезапускает приводы
и не снимает ошибки или аварийную остановку.

Остановка — **Ctrl+C**. При неожиданном движении нажмите аварийную кнопку руки.
Желаемый отступ от лица не заменяет защиту от столкновения с человеком.

Для окна камеры добавьте `--show-image`.
Другой конфиг: `./run cpu --config /путь/hardware.yaml`.

### Выбрать сглаживание при запуске

`./run` сам запускает нужный сценарий внутри Docker. Выберите **одну** команду:

| Сглаживание | Обычная камера | Стереокамера |
|---|---|---|
| Из `hardware.yaml` | `./run cpu` | `./run stereo` |
| Калман | `./run cpu --point-filter kalman` | `./run stereo --point-filter kalman` |
| One Euro | `./run cpu --point-filter one_euro` | `./run stereo --point-filter one_euro` |
| Выключено | `./run cpu --point-filter off` | `./run stereo --point-filter off` |

Аргумент действует только на этот запуск, исходный YAML не изменяется.
Коэффициенты выбранного фильтра берутся из секции `point_filter` вашего конфига:
[настройка сглаживания](cameras.md#сглаживание-точки-лица).
При следующем запуске без аргумента снова используются `enabled` и `method` из YAML.

Аргументы можно сочетать. Например, CPU с Калманом, своим конфигом и окном камеры:

```bash
./run cpu --config config/hardware.yaml --point-filter kalman --show-image
```

Проверить стереокамеру и фильтр без подключения к руке:

```bash
./run stereo --camera-only --point-filter kalman --show-image
```

| Аргумент для `cpu` и `stereo` | Назначение |
|---|---|
| `--config /путь/hardware.yaml` | Выбрать конфиг; по умолчанию `config/hardware.yaml` |
| `--point-filter off\|kalman\|one_euro` | Выключить фильтр или выбрать его метод |
| `--show-image` | Открыть изображение и рамки лиц; нужен графический сеанс |
| `--camera-only` | Только камера и распознавание, без связи с рукой |
| `--mock` | Программная модель управления вместо реальной руки; камера остаётся настоящей |
| `--domain 71` | ROS Domain ID; у внешнего драйвера камеры должен быть тот же номер |
| `--help` | Показать справку |

Поведение без лица задаётся в `tracking.idle_behavior`: `rest` — вернуться в
исходную позу, `search_sweep` — осматривать стороны,
`search_local_then_sweep` — сначала искать рядом с последним лицом, затем шире.
Скорость — в `motion.speed_scale`. После изменения YAML перезапустите ту же команду.

Перед сменой сценария остановите предыдущий через **Ctrl+C**.
Аргументы ROS вида `point_smoothing:=true` в `./run` не передаются: используйте
`--point-filter` или настройки YAML.

## Изменить настройки

Сначала остановите программу через **Ctrl+C**, измените YAML и снова запустите
ту же команду. Во время работы файл автоматически не перечитывается.

| Что изменили | Что сделать |
|---|---|
| IP руки, модель `xarm6/lite6`, стол, экран, положение камеры | Изменить `hardware.yaml` и перезапустить |
| Скорость, поиск, желаемый отступ, Калман | Изменить `hardware.yaml` и перезапустить |
| USB-путь, FPS, ROS-топики или путь к готовой калибровке | Изменить `hardware.yaml` и перезапустить |
| Камера, разрешение, FOV, зум, фокус; взаимное положение стереокамер | Подготовить подходящую калибровку и перезапустить |
| Камера со своим SDK | Запустить её ROS-драйвер отдельно и выбрать `source: ros` |

[Настройка Калмана](cameras.md#сглаживание-точки-лица),
[скорости и слежения](cameras.md#скорость-и-настройка-слежения).
Неизвестное имя настройки считается ошибкой: опечатка не пропускается молча.

Для камеры со своим SDK используйте установленный ROS-драйвер или отдельный
контейнер производителя. Его настройки задаются в конфигурации этого драйвера;
образ слежения пересобирать не нужно. [Подключение внешнего драйвера](cameras.md#внешний-драйвер-без-пересборки-проекта).

Для отдельного набора настроек можно хранить YAML и калибровку во вложенной папке,
например `config/profiles/desk/hardware.yaml`, и передавать её через `--config`.
Не редактируйте для настройки встроенные `config/moveit`, `config/control`
и `config/tracking.yaml`: параметры для настройки оборудования доступны
в `hardware.yaml`.
Программные файлы и поддерживаемые модели руки обновляются вместе с образом.

## Обновление программы и перенос

После обновления исходного кода используйте готовый образ для этой версии проекта
или выполните `./run build`. Правки `hardware.yaml` и калибровки не требуют сборки.
Сохраняйте свои измерения и адреса при обновлении примера конфига.

Для переноса подготовленного окружения:

```bash
./run export
```

Скопируйте проект вместе с `dist` на другой компьютер и выполните там `./run prepare`.
Образ подходит компьютерам той же архитектуры: Intel/AMD 64-bit либо ARM64.
