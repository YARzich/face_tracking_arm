# Камеры и геометрия

## Что измерить и указать в hardware.yaml

Единицы указаны в окончаниях имён параметров:

| Окончание / параметр | Единица | Пример |
|---|---|---|
| `_m` | Метры | `0.10` = 10 см; `0.03` = 3 см |
| `_kg` | Килограммы | `0.50` = 500 г |
| `_deg` | Градусы | `90.0` = четверть оборота |
| `_rad` | Радианы | `0.35` ≈ 20° |
| `_rad_s` | Радианы в секунду | `0.20` ≈ 11.5°/с |
| `_sec` | Секунды | `0.005` = 5 мс |
| `width`, `height` | Пиксели | `640`, `480` |
| `fps`, `_fps` | Кадры в секунду | `30.0` = 30 кадров/с |

В списках `xyz` и `size` порядок — `[X, Y, Z]`; в `rpy` — повороты вокруг X, Y, Z.

| Секция | Что заполнить |
|---|---|
| `robot` | IP и положение основания от пола (`base_xyz_m`, `base_rpy_deg`) |
| `table` | Форма, размеры и положение столешницы для проверки столкновений |
| `monitor` | Реальные габариты с креплением, масса, положение центра относительно фланца `link6` |
| `camera_mount` | Корпус камеры относительно центра монитора, габариты, масса |
| `mono_cpu.left` | Устройство/топики, разрешение, FPS, калибровка, optical frame и её положение |
| `stereo.left/right` | Те же данные отдельно слева/справа; стереобаза и синхронизация |
| `tracking.idle_behavior` | `rest`, `search_sweep` либо `search_local_then_sweep` |
| `motion.speed_scale` | Начать с `0.25`; затем при успешной проверке повысить, максимум `1.0` |
| `motion.rest_joints_deg/search_joints_deg` | Исходная поза и поза поиска; шесть углов суставов |

В осях монитора/корпуса **X направлен вперёд от экрана, Y влево, Z вверх**.
В optical frame камеры **X вправо на изображении, Y вниз, Z вперёд**.
Указанный по умолчанию `optical_rpy_deg: [-90, 0, -90]` делает это преобразование.
`optical_xyz_m` — положение центра объектива относительно центра корпуса.
Измерьте своё крепление и замените размеры в конфиге.

**Зачем задавать стол:** контроллер использует его размеры, чтобы проверять
столкновения руки и экрана со столешницей. Камера сама стол не измеряет.
Неверные размеры могут перекрыть свободное место или оставить часть стола
вне проверки.

Координаты основания и центра стола задаются в одной системе `world`.
За начало удобно принять точку на полу прямо под основанием: тогда у основания
X=0, Y=0, а Z равно высоте установки. Z направлен вверх.

Для прямоугольного стола поставьте `shape: box`, а `dimensions_m` задайте
как `[длина_X, ширина_Y, толщина]`. Например, при основании на высоте 0.80 м
и толщине столешницы 0.04 м её центр по Z равен 0.78 м. Для круглого стола
`dimensions_m` — `[толщина, радиус]`. Смещение основания от центра стола
учтите в координатах `center_m`.

Проверьте позы `rest_joints_deg` и `search_joints_deg` в Studio на малой скорости
с установленным экраном. Углы указаны по порядку суставов 1–6.

### Что означают четыре настройки stereo

| Параметр | Что выбрать |
|---|---|
| `source` | `ros`: отдельно запускаете ROS-драйвер своей камеры, проект читает его изображения. `usb`: проект сам открывает два USB-устройства из `left.device` и `right.device`. |
| `rectification` | `rectified`: драйвер уже исправил искажения объективов и выровнял изображения. `raw`: проект делает это сам по парной калибровке. Для двух обычных USB-камер выберите `raw`. |
| `baseline_m` | Расстояние между оптическими центрами объективов в **метрах**. `0.0` означает «взять из калибровки», а не нулевое расстояние. Если драйвер не передаёт его, укажите значение из парной калибровки или паспорта камеры, например `0.08` для 8 см. |
| `sync_slop_sec` | Допустимая разница времени кадров в **секундах**. При `0.005` подходят пары с разницей до 5 мс; кадры с большей разницей не используются вместе. Параметр не заставляет камеры снимать одновременно. |

Выравнивание нужно, чтобы одна и та же точка лица попадала на одну строку
левого и правого изображения. По её смещению вдоль строки вычисляется расстояние.
Для слежения за движением включите аппаратную синхронизацию камер в их драйвере.

### Камера со своим ROS-драйвером

1. Установите драйвер **конкретной модели** по инструкции производителя.
2. Включите левое/правое изображения и CameraInfo, желательно 640×480, 30 FPS.
3. В `stereo` оставьте `source: ros`; впишите имена каналов с изображениями
   (`image_topic`) и калибровкой (`info_topic`) слева и справа. Посмотреть их
   в терминале драйвера: `ros2 topic list`. Имя системы координат камеры (`frame_id`) возьмите из
   `ros2 topic echo ИМЯ_CAMERA_INFO --once --qos-reliability best_effort`.
4. Поставьте `rectification: rectified`, если драйвер уже выровнял изображения;
   для исходных изображений — `raw` и парная калибровка.
5. Оставьте `baseline_m: 0.0`, если драйвер передаёт расстояние между объективами
   в калибровке. Иначе укажите его в метрах. Это не заменяет выравнивание изображений.
6. Запустите драйвер с `ROS_DOMAIN_ID=71`. Начните с `sync_slop_sec: 0.005`.
   Изображение и его `CameraInfo` должны иметь одинаковые время кадра и `frame_id`.

Если драйвер работает на другом компьютере, синхронизируйте часы компьютеров.

**Положение камеры на руке (TF).** TF — связи между системами координат руки,
корпуса камеры и объективов. По умолчанию проект задаёт эти связи из конфига:
оставьте `camera_mount.publish_optical_tf: true` и отключите TF в драйвере камеры.
Если используете связи между объективами из драйвера, поставьте
`camera_mount.publish_optical_tf: false`,
а `body_frame` — имя корневого корпуса драйвера (например, `camera_link`).
Тогда проект задаёт положение корпуса на мониторе, а драйвер — положение
объективов внутри корпуса. Для одной и той же связи должен работать только
один источник TF.


## Частота обработки

`perception.max_processing_fps` ограничивает нагрузку на процессор. Для слежения
начните с 15–20 кадров в секунду. Выбор лица работает и при редких свежих кадрах,
но требует трёх наблюдений: при 1 кадре в секунду подтверждение занимает
около 2 с от первого обнаружения. При такой частоте рука может переходить
в ожидание между кадрами; для плавного сопровождения увеличьте частоту.

## USB-камера не открывается

Проверьте `device` через `./run devices`. Используйте поддерживаемое камерой
разрешение и формат: для MJPEG — `pixel_format: mjpeg2rgb`, для YUYV —
`pixel_format: yuyv2rgb`. Остановите другие программы, использующие эту камеру.

После смены разрешения или фокуса повторите `./run calibrate cpu`
(для стереопары — `./run calibrate stereo`).
