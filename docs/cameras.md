# Камеры и геометрия

## Что измерить и указать в hardware.yaml

Единицы указаны в окончаниях имён параметров:

| Окончание / параметр | Единица | Пример |
|---|---|---|
| `_m` | Метры | `0.10` = 10 см; `0.03` = 3 см |
| `_kg` | Килограммы | `0.50` = 500 г |
| `_deg` | Градусы | `90.0` = четверть оборота |
| `_rad` | Радианы | `0.35` ≈ 20° |
| `_rad_s` | Радианы в секунду | `0.20` ≈ 11.5°/с |
| `_rad_s2`, `_rad_s3` | Рад/с², рад/с³ | Ускорение и рывок суставов |
| `_mps`, `_radps` | М/с, рад/с | Линейная и угловая скорости цели |
| `_mps2` | М/с² | Ожидаемое ускорение лица в фильтре Калмана |
| `_hz` | Герцы | Частота фильтра |
| `_sec` | Секунды | `0.005` = 5 мс |
| `width`, `height` | Пиксели | `640`, `480` |
| `fps`, `_fps` | Кадры в секунду | `30.0` = 30 кадров/с |

В списках `xyz` и `size` порядок — `[X, Y, Z]`; в `rpy` — повороты вокруг X, Y, Z.

| Секция | Что заполнить |
|---|---|
| `robot` | Модель (`xarm6`/`lite6`), IP и положение основания от пола (`base_xyz_m`, `base_rpy_deg`) |
| `table` | Форма, размеры и положение столешницы для проверки столкновений |
| `monitor` | Реальные габариты с креплением, масса, положение центра относительно фланца `link6` |
| `camera_mount` | Корпус камеры относительно центра монитора, габариты, масса |
| `mono_cpu.left` | Устройство/топики, разрешение, FPS, калибровка, optical frame и её положение |
| `stereo.left/right` | Те же данные отдельно слева/справа; стереобаза и синхронизация |
| `tracking.idle_behavior` | `rest`, `search_sweep` либо `search_local_then_sweep` |
| `motion.speed_scale` | Множитель трёх массивов `limits`; начать с `0.25` |
| `limits` | Пределы скорости, ускорения и рывка каждого из шести суставов |
| `controller` | Скорость цели, чувствительность слежения, зазоры и точные настройки контроллера |
| `motion.rest_joints_deg/search_joints_deg` | Исходная поза и поза поиска; шесть углов суставов |
| `point_filter` | Включение сглаживания и настройки отдельно для обычной камеры и стерео |

В осях монитора/корпуса **X направлен вперёд от экрана, Y влево, Z вверх**.
В optical frame камеры **X вправо на изображении, Y вниз, Z вперёд**.
Указанный по умолчанию `optical_rpy_deg: [-90, 0, -90]` делает это преобразование.
`optical_xyz_m` — положение центра объектива относительно центра корпуса.
Измерьте своё крепление и замените размеры в конфиге.

Контроллер использует размеры стола, чтобы проверять
столкновения руки и экрана со столешницей. Камера сама стол не измеряет.
Неверные размеры могут перекрыть свободное место или оставить часть стола
вне проверки.

Все нули в `table.dimensions_m` отключают геометрию стола: два нуля для
`cylinder`, три для `box`. `monitor.size_m: [0, 0, 0]` отключает геометрию экрана.
Объекты не создаются с нулевым объёмом: они исключаются из модели столкновений.
Камера и её TF остаются, `robot.base_xyz_m` и координаты крепления не обнуляются.
Коллизии с отключённым объектом не проверяются. Частичные нули и отрицательные
размеры отклоняются. У отсутствующего экрана можно указать `monitor.mass_kg: 0`;
при ненулевых размерах масса должна быть положительной.

Координаты основания и центра стола задаются в одной системе `world`.
За начало удобно принять точку на полу прямо под основанием: тогда у основания
X=0, Y=0, а Z равно высоте установки. Z направлен вверх.

Для прямоугольного стола поставьте `shape: box`, а `dimensions_m` задайте
как `[длина_X, ширина_Y, толщина]`. Например, при основании на высоте 0.80 м
и толщине столешницы 0.04 м её центр по Z равен 0.78 м. Для круглого стола
`dimensions_m` — `[толщина, радиус]`. Смещение основания от центра стола
учтите в координатах `center_m`.

Проверьте позы `rest_joints_deg` и `search_joints_deg` в Studio на малой скорости
с установленным экраном. Углы указаны по порядку суставов 1–6.

Внутренние контакты жёсткой сборки «фланец — экран — камера» исключены
из проверки столкновений: взаимное положение этих деталей не меняется.
Столкновения сборки с остальными звеньями руки, столом и окружением
проверяются. Указывайте реальные размеры и положение крепления.

### Пути к файлам

`calibration_file` и `perception.model_dir` — пути на компьютере, с которого
запускается `./run`. Можно использовать полный путь или относительный путь
от папки выбранного `hardware.yaml`. `~` означает домашнюю папку пользователя.
Скрипт сам подключает нужные файлы к контейнеру.

Пустой `calibration_file: ''` при USB-запуске выбирает результат `./run calibrate`:
`calibration/mono_cpu/left.yaml` либо `calibration/stereo/{left,right}.yaml`
рядом с конфигом. Для своего файла всегда передавайте один и тот же `--config`
при калибровке и запуске. Если `calibration_file` непустой, используется именно
этот путь; новая калибровка не меняет его автоматически.

Для `source: ros` калибровку передаёт драйвер через `CameraInfo`.
Пути `calibration_file` в этом режиме не используются.

### Основные настройки стереокамеры

| Параметр | Что выбрать |
|---|---|
| `source` | `ros`: отдельно запускаете ROS-драйвер своей камеры, проект читает его изображения. `usb`: проект сам открывает два USB-устройства из `left.device` и `right.device`. |
| `rectification` | `rectified`: драйвер уже исправил искажения объективов и выровнял изображения. `raw`: проект делает это сам по парной калибровке. Для двух обычных USB-камер выберите `raw`. |
| `baseline_m` | Расстояние между оптическими центрами объективов в **метрах**. `0.0` означает «взять из калибровки», а не нулевое расстояние. Если драйвер не передаёт его, укажите значение из парной калибровки или паспорта камеры, например `0.08` для 8 см. |
| `sync_slop_sec` | Допустимая разница времени кадров в **секундах**. При `0.005` подходят пары с разницей до 5 мс; кадры с большей разницей не используются вместе. Параметр не заставляет камеры снимать одновременно. |

Выравнивание нужно, чтобы одна и та же точка лица попадала на одну строку
левого и правого изображения. По её смещению вдоль строки вычисляется расстояние.
Для слежения за движением включите аппаратную синхронизацию камер в их драйвере.

### Диапазон стереоглубины

`stereo.num_disparities: 128` — ширина поиска смещений между левым и правым
изображением, в пикселях. Чем ближе лицо, шире база камер или выше разрешение,
тем больше может быть смещение. Если близкое лицо обнаруживается, но глубина
для него не получается, можно попробовать `256`. Это увеличит нагрузку на CPU.
Значение должно быть положительным и кратным 16.

`stereo.block_size: 5` — сторона окна сопоставления, в пикселях. При необходимости
можно попробовать `3` или `7`: большое окно усредняет больше деталей, но может
смешивать лицо с фоном. Разрешено положительное нечётное число.
Это параметры [OpenCV StereoSGBM](https://docs.opencv.org/4.x/d2/d85/classcv_1_1StereoSGBM.html).

Ширина кадра должна быть больше `num_disparities + block_size // 2`,
а обе стороны кадра — не меньше `block_size`. Неподходящие значения отклоняются
с пояснением. Эти настройки не заменяют парную калибровку и синхронизацию.

### Камера со своим ROS-драйвером

1. Установите драйвер **конкретной модели** по инструкции производителя.
2. Включите левое/правое изображения и CameraInfo, желательно 640×480, 30 FPS.
3. В `stereo` оставьте `source: ros`; впишите имена каналов с изображениями
   (`image_topic`) и калибровкой (`info_topic`) слева и справа. Посмотреть их
   в терминале драйвера: `ros2 topic list`. Имя системы координат камеры (`frame_id`) возьмите из
   `ros2 topic echo ИМЯ_CAMERA_INFO --once --qos-reliability best_effort`.
4. Поставьте `rectification: rectified`, если драйвер уже выровнял изображения;
   для исходных изображений — `raw` и парная калибровка.
5. Оставьте `baseline_m: 0.0`, если драйвер передаёт расстояние между объективами
   в калибровке. Иначе укажите его в метрах. Это не заменяет выравнивание изображений.
6. Запустите драйвер с `ROS_DOMAIN_ID=71`. Начните с `sync_slop_sec: 0.005`.
   Изображение и его `CameraInfo` должны иметь одинаковые время кадра и `frame_id`.

Если драйвер работает на другом компьютере, синхронизируйте часы компьютеров.
Для одной обычной камеры с внешним драйвером доступны те же `source: ros`,
топики и optical frame в `mono_cpu`. `mono_cpu.sync_slop_sec: 0.0` требует
совпадения времени изображения и `CameraInfo`. Небольшой допуск, например
`0.005`, задаётся в секундах; он не исправляет старую или неверную калибровку
и не заменяет правильные временные метки драйвера.

**Положение камеры на руке (TF).** TF — связи между системами координат руки,
корпуса камеры и объективов. По умолчанию проект задаёт эти связи из конфига:
оставьте `camera_mount.publish_optical_tf: true` и отключите TF в драйвере камеры.
Если используете связи между объективами из драйвера, поставьте
`camera_mount.publish_optical_tf: false`,
а `body_frame` — имя корневого корпуса драйвера (например, `camera_link`).
Тогда проект задаёт положение корпуса на мониторе, а драйвер — положение
объективов внутри корпуса. Для одной и той же связи должен работать только
один источник TF.

Даже при внешнем TF заполните `optical_xyz_m` и `optical_rpy_deg` точно так же,
как в драйвере: контроллер использует их во внутренней модели направления камеры.
В этом режиме создаётся отдельная внутренняя система `tracking_gaze_optical`;
это имя зарезервировано и не заменяет `frame_id` изображений.


## Частота обработки

`perception.max_processing_fps` ограничивает нагрузку на процессор. Для слежения
начните с 15–20 кадров в секунду. Выбор лица работает и при редких свежих кадрах,
но требует трёх наблюдений: при 1 кадре в секунду подтверждение занимает
около 2 с от первого обнаружения. При такой частоте рука может переходить
в ожидание между кадрами; для плавного сопровождения увеличьте частоту.

## Сглаживание точки лица

В шаблоне `hardware.yaml` включён фильтр Калмана. Он сглаживает **3D-точку,
которую получает управление**. Рамка лица и красная точка на изображении
показывают исходный результат детектора и не сглаживаются.

```yaml
point_filter:
  enabled: true
  method: kalman
  reset_after_sec: 0.25
  mono_cpu:
    measurement_std_m: 0.03
    acceleration_std_mps2: 1.0
  stereo:
    measurement_std_m: 0.02
    acceleration_std_mps2: 1.5
```

`./run cpu` использует `mono_cpu`, а `./run stereo` — `stereo`.
Для отключения поставьте `enabled: false`.
Для одного запуска без изменения YAML используйте `--point-filter`:
`./run cpu --point-filter kalman`, `./run cpu --point-filter one_euro`
или `./run cpu --point-filter off`. Для стерео замените `cpu` на `stereo`.
Аргумент меняет только включение и метод; численные настройки остаются из YAML.

| Параметр | Как влияет |
|---|---|
| `measurement_std_m` | Ожидаемый шум координат, метры. Больше — сильнее сглаживание, медленнее реакция |
| `acceleration_std_mps2` | Ожидаемые изменения скорости лица, м/с². Меньше — сильнее сглаживание, медленнее реакция |
| `reset_after_sec` | После такого перерыва между измерениями фильтр начинает заново; секунды |

Начните со значений шаблона. Для более спокойной точки немного увеличьте
`measurement_std_m` **либо** уменьшите `acceleration_std_mps2` и проверьте
как неподвижное лицо, так и быстрый поворот головы. Меняйте один параметр за раз:
слишком сильное сглаживание заставляет руку отставать.

После правки остановите программу через Ctrl+C и запустите снова. Пересборка
не нужна. Фильтр не исправляет ошибки калибровки или систематическую ошибку
оценки расстояния от обычной камеры. Проверка `--camera-only` выполняется
без связи с рукой; при ней оставляйте камеру неподвижной.

Для другого метода укажите `method: one_euro`. Его необязательные настройки
добавляются внутри `point_filter`:

```yaml
  one_euro:
    min_cutoff_hz: 1.5
    beta: 32.0
    derivative_cutoff_hz: 1.0
```

Без секции `point_filter` сглаживание выключено. Чтобы включить его в своём
конфиге, добавьте секцию из примера выше.

## USB-камера не открывается

Проверьте `device` через `./run devices`. Используйте поддерживаемое камерой
разрешение и формат: для MJPEG — `pixel_format: mjpeg2rgb`, для YUYV —
`pixel_format: yuyv2rgb`. Остановите другие программы, использующие эту камеру.

После смены разрешения, FOV, зума или фокуса повторите `./run calibrate cpu`
(для стереопары — `./run calibrate stereo`).


## Logitech BRIO C1000e и USB-настройки

USB-камеры открываются штатным `usb_cam`. `width`, `height`, `fps`, `pixel_format`
задают формат потока. `driver_parameters` принимает параметры драйвера:
`brightness`, `contrast`, `saturation`, `sharpness`, `gain`, `auto_white_balance`,
`white_balance`, `autoexposure`, `exposure`, `autofocus`, `focus`, `av_device_format`.
Также доступен `io_method`: `mmap` (по умолчанию), `read` или `userptr`.
Менять его нужно только если этого требует USB-устройство/драйвер.
Автоматические режимы — `true/false`; ручные численные значения зависят от камеры.
Неизвестные имена отклоняются. Параметр `fov` в этом разделе не поддерживается.

`control_values` задаёт именно аппаратные настройки, с проверкой доступности,
допустимого значения и отдельным чтением результата. Для BRIO:

```yaml
control_values:
  logitech_brio_fov: '90'
  zoom_absolute: minimum
```

`minimum` означает нижнюю границу зума, которую сообщила сама камера, а не
предполагаемое число `100`. Режим BRIO 90° указан **по диагонали**; реальное поле
кадра зависит и от выбранного формата. Для расчёта координат используются
измеренные параметры калибровки, а не это число. [Спецификация Logitech](https://hub.sync.logitech.com/brio/post/brio-brio-4k-specifications-BJKhhCqWmecRhPD).

Режим FOV доступен через vendor UVC extension. Его применяет отдельная программа
[cameractrls](https://github.com/soyersoyer/cameractrls), включённая в образ под
LGPL-3.0-or-later. Она определяет поддержку по USB ID и дескрипторам конкретного
устройства. Один лишь текст «C1000e» не гарантирует поддержку всех ревизий.
Неподдерживаемый control или несовпадение прочитанного значения останавливает запуск.
Не задавайте одну настройку одновременно через `driver_parameters` и `control_values`.

В терминале строка `verified hardware controls` означает проверку до запуска
видеопотока. При первом подключении проверьте изображение через `--camera-only`:
эта проверка не доказывает, что конкретная прошивка сохраняет настройки после
начала потока или переподключения USB. После переподключения перезапустите команду.

Для `source: ros` захват и аппаратные настройки полностью принадлежат внешнему
драйверу. Поля `device`, `width`, `height`, `fps`, `pixel_format`, `driver_parameters`
и `control_values` этого проекта используются только при `source: usb`.

## Скорость и настройка слежения

Все значения ниже читаются из внешнего `hardware.yaml` при каждом запуске.

| Настройка | Что меняет |
|---|---|
| `limits.max_velocity_rad_s` | Максимальная скорость каждого сустава |
| `limits.max_acceleration_rad_s2` | Максимальное ускорение каждого сустава |
| `limits.max_jerk_rad_s3` | Скорость изменения ускорения; влияет на плавность |
| `motion.speed_scale` | Умножает все три массива `limits` |
| `controller.maximum_linear_reference_mps` | Скорость изменения желаемой позиции экрана |
| `controller.maximum_angular_reference_radps` | Скорость изменения желаемого направления |
| `controller.position_gain`, `orientation_gain` | Насколько активно сокращается ошибка позиции/направления |
| `controller.position_deadband_m`, `pointing_deadband_rad` | Малые ошибки, на которые не нужно реагировать |
| `controller.hard_clearance_m` | Минимальный геометрический зазор при проверке столкновений |
| `controller.joint_position_margin_rad` | Предпочтительный запас до границы сустава |
| `tracking.minimum_face_distance_m` | Желаемое расстояние от лица |
| `tracking.safe_reach_radius_m` | Область, в которой выбирается позиция экрана |
| `tracking.face_target_freshness_timeout_sec` | Необязательный срок свежести точки лица, секунды; после него слежение считает измерение устаревшим |

`minimum_face_distance_m` задаёт желаемую дистанцию, а не жёсткую границу:
приоритет имеет наведение на лицо. Точность расстояния зависит от камеры.
`safe_reach_radius_m` относится к выбору желаемой позиции экрана, а не к
физическому ограничителю движения.

`face_target_freshness_timeout_sec` обычно менять не нужно. Если указываете его,
`return_to_rest_delay_sec` должен быть строго больше. Увеличение срока свежести
не ускоряет обработку и позволяет дольше пользоваться старым измерением.

При значениях из примера `speed_scale: 1.0` означает **1 рад/с ≈ 57.3°/с**,
2 рад/с² и 20 рад/с³ для каждого сустава. При `0.25` — 0.25 рад/с, 0.5 рад/с²
и 5 рад/с³. Это настройки проекта, а не максимумы производителя.
Скорость цели экрана 0.18 м/с и угловая скорость 0.70 рад/с задаются отдельно;
фактическое движение всё равно ограничено суставами и свободным пространством.

Скорость выше заводского предела выбранной модели или активного Reduced Mode
отклоняется с ошибкой вместо скрытого уменьшения. Ускорение и рывок — выбранные
пределы проекта; отсутствие программного верхнего порога не означает, что любая
настройка подходит физической руке. Углы остаются ограничены описанием производителя
и активными ограничениями контроллера руки.

Дополнительные допустимые имена `controller` перечислены в
[`hardware_schema.py`](../python/face_tracking_bringup/hardware_schema.py),
начальные значения — в
[`collision_aware_servo.yaml`](../config/moveit/collision_aware_servo.yaml).
Меняйте их через секцию `controller` внешнего файла, а не внутри образа.
Численные требования алгоритма (например, положительные допуски решателя и
согласованный зазор) проверяются при запуске; неверная конфигурация вызывает ошибку.
`monitor_guard_joint_name: ''` отключает дополнительное сужение одного сустава.
`monitor_near_distance_lipschitz_m_per_rad` вычисляется по геометрии и не
настраивается вручную. Поле принимается для совместимости; заданное в YAML
значение не меняет результат, о чём программа сообщает при запуске.

## Внешний драйвер без пересборки проекта

Для камеры с собственным SDK используйте её установленный ROS 2-драйвер либо
отдельный образ этого драйвера. Для контейнера нужны сеть `host`, `ROS_DOMAIN_ID=71`
и доступ к устройствам камеры по инструкции производителя.
SDK и его зависимости устанавливаются в окружение драйвера.

Затем выберите `source: ros` и пропишите существующие топики/кадры. Для совместимости
используйте ROS 2 Jazzy; проверьте доступность `sensor_msgs/Image` и
`sensor_msgs/CameraInfo` из контейнера драйвера. Параметры конкретного SDK остаются
в его конфигурации. Замена или обновление такого контейнера не меняет образ слежения.
