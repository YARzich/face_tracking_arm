# Overlay `controller_manager` для Gazebo sim time

Перед запуском компактной xArm6 Gazebo-сцены соберите workspace overlay. Он
содержит только `controller_manager` версии `4.48.1` (`b7f1a5d420443c7a079f4c81e80d5e39759acf4c`)
с clock fix из [ros2_control PR #3684](https://github.com/ros-controls/ros2_control/pull/3684).
Upstream лицензия пакета — Apache-2.0, PR пока открыт и ещё не вошёл в релиз.
Изменение исправляет передачу stamp симуляции контроллеру; это точечный clock
fix, а не общая оптимизация производительности. В xArm6 Gazebo plugin также
используется proportional gain `1.0`; настройки lite6 не меняются.

Из корня `ros2_ws`:

```bash
source /opt/ros/jazzy/setup.bash
bash src/face_tracking_arm/tools/build_controller_manager_clock_overlay.sh
source install/setup.bash
ros2 launch face_tracking_arm tracking_sim.launch.py
```

Скрипт собирает только пакет `controller_manager` для текущего workspace.
Он проверяет upstream pin `4.48.1`, не устанавливает зависимости и не пишет
в `/opt/ros`. После очистки `build` или `install` повторно запустите скрипт.

До добавления раскрытия на xArm6 compact-demo прошли три nominal run до достижения ориентации
(4.850, 4.899 и 4.900 с), четыре phase checks и один runtime run через workspace
overlay. В этом последнем запуске ориентация достигнута за 4.900 с; расстояние
до marker было 0.835 м, а полный подход занял около 9–10 с. Робот удерживал FACE
10 с без rearm, потери пути, отказа планирования или limiter event. Это результат
одной Gazebo-сцены и её профиля, не подтверждение полного манёвра за 5 секунд,
других конфигураций или аппаратных сценариев.

В текущем варианте проверенное раскрытие включено во временной профиль и
настройку return. При пределах 3.1/19/400 последняя серия дала 5.300, 5.509 и
5.270 с от начала подготовки до подтверждённого возврата FACE. Дистанция при
возврате во всех трёх запусках внутри 0.37–0.43 м. В это время входит прежнее
подтверждение устойчивого наведения в течение 0.30 с; строгий критерий всего
цикла ≤5 с **не выполнен**. Четыре проверки множителей 0.8 прошли проверки
здоровья; common/return/fold/turn заняли соответственно 6.330/5.572/5.440/5.750 с.
Задержка подготовки из-за отменённого фонового запроса устранена штатным
сигналом завершения планировщику; в этой серии подготовка занимала 0.09–0.11 с.

В двух номинальных запусках после перестройки зарегистрирован controlled re-arm
из-за отказа проверки свежести состояния суставов, в одном — внутри контрольных
10 с FACE. Потери пути, отклонённых планов и событий ограничителя не было,
но серия в целом **FAIL**. Причина этих двух отказов пока не установлена;
подробная диагностика snapshot добавлена без изменения правил свежести.
Три повтора с этой диагностикой прошли проверки здоровья, но не воспроизвели
отказ; это не означает его устранения. Их времена — 5.270/5.550/5.540 с,
поэтому строгая временная приёмка также не пройдена. Отчёт и графики:
`log/compact5s_20261029/cancel_validation/cancel_validation_summary.md` и
`actual_velocity_comparison.pdf` от корня workspace.

Upstream native fixture не запускался: отсутствует `hardware_interface_testing`
с `test_actuator`; runtime-прогоны не заменяют этот unit test.
