Что стоит за картинкой

Только обычное слежение FACE. Все примеры нарисованы локально; страница не подключается к роботу. Исходники проверены 18 октября 2026.

Где учебное упрощение, а где реальный алгоритм

На экране — точная геометрия условной плоской руки с двумя суставами. В проекте — шесть суставов, трёхмерная геометрия и несколько компонент задач. Числа суставных скоростей на рисунках относятся только к учебной руке.

В QP-демонстрации минимизируется (a·v − b)² + λ‖v‖². Малый штраф на величину скоростей выбирает один ответ среди похожих. Для двух переменных достаточно аналитического решения с проверкой границ многоугольника; OSQP в браузере не запускается. В проекте OSQP решает выпуклую QP методом ADMM. Там также есть штраф на изменение предыдущей скорости.

Полуплоскость «рядом препятствие» — иллюстрация ограничения скорости сближения, а не расстояние из нарисованной сцены. Проверка остановки тоже схематична. Последний экран демонстрирует только основной цикл наведения, без полного набора ограничений и второй задачи.

Для ошибки использованы настройки проекта: усиление 4 с⁻¹, мёртвая зона 0,005 рад ≈ 0,29°, предел углового запроса 0,70 рад/с ≈ 40,1°/с. В примере лицо после смещения неподвижно, поэтому опережающая добавка равна нулю.

Какая библиотека что делает
  • Собственный код: строит задачи и ограничения, интегрирует скорости в следующий шаг, проверяет шаг и тормозной хвост, ведёт очередь.
  • OSQP: численно решает две ступени QP. На первой — наведение и крен, на второй — положение с сохранением достигнутой скорости первой задачи.
  • MoveIt / FCL: модель, кинематика, якобианы, расстояния и столкновения.
  • MoveIt Servo: в этой цепочке используется утилита упаковки сообщения composeTrajectoryMessage. Интегрирование найденных скоростей выполняет код проекта.
  • JointTrajectoryController (JTC): получает точки углов с временем. Здесь передаются только позиции; при настройке splines интерполяция между такими точками линейная.

Номинальные 100 Гц — настройка периода, а не измеренная гарантия быстродействия. Старт следующего расчёта берётся с конца принятой очереди, а обратная связь проверяет фактическое состояние. Рабочая область OSQP создаётся заново для ступени; готовую факторизацию между тактами этот код не переиспользует.
