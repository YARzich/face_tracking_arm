# Три отдельных теста 3D-точки лица

Gazebo Harmonic, ROS 2 Jazzy. В сцене только человек и неподвижные камеры
на высоте 1.65 м. Детектор находит рамку лица, выбранный способ оценивает глубину,
а параметры камеры из CameraInfo используются для расчёта координат XYZ в метрах. Руки в этих
запусках нет. Выбирается ближайшее видимое лицо с пригодной оценкой глубины;
выбор подтверждается несколькими кадрами и использует задержку переключения.
Это сопоставление положений, без распознавания личности.

## Запуск

Подготовьте окружение и модель человека по
[инструкции 2D-теста](face_detection_test.md#подготовка).
Запускайте **один вариант за раз**:

```bash
source ~/ros2_ws/install/setup.bash
ros2 launch face_tracking_arm face_depth_cpu.launch.py
```

```bash
ros2 launch face_tracking_arm face_depth_gpu.launch.py
```

```bash
ros2 launch face_tracking_arm face_depth_stereo.launch.py
```

GPU-вариант экспериментальный: **ошибка расстояния в тестовой сцене достигает
1–2 м**. Не используйте его для точного измерения дистанции.

При запуске открываются Gazebo и RViz: изображение с рамкой и XYZ, сетка мира, оси камеры и 3D-маркеры.
Зелёный — оценка, синий — эталонная поверхность лица из Gazebo. Близкие
маркеры могут перекрываться. Численная ошибка доступна в `/face_test/depth_error`.
Можно двигать **человека** инструментом Transform в Gazebo. Камеры оставлять
неподвижными: статические TF заданы для их исходной позы.

Общие аргументы:

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| `detector` | `yunet` | Также `yolov5n_face` или `yolo_facev2n` |
| `headless` | `false` | `true` отключает оба окна, рендеринг камер остаётся |
| `show_image` | `true` | `false` отключает только RViz |
| `reference` | `true` | Независимая проверка по глубине Gazebo; можно отключить |
| `threads` | `2` | Потоки OpenCV/детектора |
| `confidence` | `0.6` | Порог обнаружения лица |
| `face_width_m` | `0.16` | Принятая физическая ширина лица для CPU |
| `baseline` | `0.08` | Расстояние между стереокамерами, м; допустимо 0.02–0.25 |
| `depth_input_size` | `280` | Размер входа GPU-сети; кратный 14, минимум 140 |
| `depth_scale` | `1.0` | Явный ручной масштаб GPU-глубины после отдельной калибровки |

Пути `model_dir`, `assets_dir`, `python_executable` совпадают с 2D-тестом.
`depth_weights` и `depth_source` позволяют указать другие места хранения
**той же метрической Small-модели**. Обычная relative-depth модель сюда не подходит.
В проверенной модели FaceV2 детекции лица в этой сцене отсутствуют.
Для сравнения способов оценки глубины используйте YuNet или YOLOv5n-face.

## Как оценивается расстояние

**CPU, одна RGB-камера.** Используется `Z = fx × face_width_m / bbox_width_px`.
Это быстрый приблизительный расчёт для лица анфас. Размер головы,
поворот и границы рамки меняют результат. Размер из симулятора не подставляется.
Для реальной камеры понадобится её калибровка; автоматически узнать метры
из одного изображения таким способом нельзя.

**GPU, одна RGB-камера.** Официальная
[Depth Anything V2 Metric Hypersim Small](https://huggingface.co/depth-anything/Depth-Anything-V2-Metric-Hypersim-Small)
предсказывает глубину в метрах; берётся медиана центральной области лица.
Выбрана версия Small, 24.8 млн параметров, Apache-2.0. Это indoor-модель с
максимальной глубиной 20 м; выход проекта ограничен диапазоном 0.25–8 м.
Метрическая модель тоже может систематически ошибаться в непривычной сцене.
`depth_scale` не вычисляется автоматически по эталону Gazebo. Начальный вход
280 выбран для скорости. Увеличение до 392/518 не устраняет систематическую
ошибку глубины. Этот режим требует NVIDIA CUDA; видеокарты AMD/Intel
и автоматический переход на CPU не поддерживаются.

**Стерео, две RGB-камеры.** OpenCV StereoSGBM находит смещение пикселей
между синхронными выровненными изображениями. Глубина равна `fx × baseline / disparity`
с учётом возможного различия главных точек. База читается из CameraInfo правой
камеры. Геометрия мира, TF и матрица проекции генерируются из одного аргумента
`baseline`. Газебовская карта глубины в расчёт не попадает. При базе 8 см и
128 диспаратностях рабочая ближняя граница около 35–40 см; вдали и на
нетекстурированных участках надёжность снижается. Реальные камеры требуют
калибровки, исправления искажений, выравнивания изображений и синхронизации.

Стерео работает на CPU; отдельная видеокарта нужна только самому Gazebo для
отрисовки. Построение облака точек для получения одной координаты не требуется.

## Дополнительная подготовка GPU

Скрипт загружает небольшой официальный исходный код по фиксированному commit.
Веса 99 МБ скачиваются **только при явном флаге**. Проверяется их SHA-256;
чужой существующий файл с другим хешем не перезаписывается. Исходный код модели, LICENSE и сведения об источнике сохраняются в кеше.

```bash
cd ~/ros2_ws/src/face_tracking_arm
python3 scripts/prepare_metric_depth.py --download-weights
```

Нужны совместимые CUDA-сборки PyTorch и torchvision в perception_venv.
Выберите совместимую сборку по GPU и драйверу через
[официальный установщик PyTorch](https://pytorch.org/get-started/locally/).
CPU/стерео эти зависимости не используют. Launch сам ничего не скачивает.

Исходный код: `DepthAnything/Depth-Anything-V2`, commit
`a561b849ebae10a6f5ef49e26c83cbbcd36c71bf`, каталог `metric_depth/depth_anything_v2`.
Веса: revision `3bc65d4e14a6786a61acec16453c50e12bf5f338`,
`depth_anything_v2_metric_hypersim_vits.pth` (99 222 290 байт), SHA-256
`b782898d8a3e8be1f639de33837ed85e9b4b73e40f8f5e5cd99067588d722545`.
Apache-2.0 относится к Small; другие размеры модели имеют другие условия.

## ROS-контракт и свежесть данных

- `/face_test/center_3d`: `geometry_msgs/PointStamped`, метры,
  `face_test_camera_optical_frame`: X вправо, Y вниз, Z вперёд. Z — глубина,
  расстояние по лучу равно длине вектора XYZ.
- `/face_test/center_world`: та же точка в `world`, Z вверх.
- `/face_test/detections`: все 2D-рамки, как в [2D-тесте](face_detection_test.md).
- `/face_test/debug_image`: выбранный режим, точка и время обработки.
- `/face_test/depth_status`: `DiagnosticArray`, состояние, `point_valid`, XYZ,
  число лиц и `processing_ms` (без доставки/очереди/отрисовки).
- `/face_test/depth_estimate`: `32FC1` в метрах для GPU/стерео, только при подписке.
- `/face_test/reference_3d`, `/face_test/depth_error`: независимое сравнение
  оценки с поверхностью лица по тому же лучу. Это проверка глубины в выбранной
  точке, а не точности нахождения анатомического центра головы.

Связанные изображения/CameraInfo объединяются **по точному stamp**, frames
проверяются отдельно. Входные очереди и буфер синхронизатора содержат до четырёх сообщений;
накопления длинной истории нет. Выход сохраняет stamp исходного кадра,
в том числе после преобразования в world. Все узлы используют `use_sim_time`.
Если TF на время кадра ещё не пришёл, world-выход ожидает его неблокирующе
для последней точки, до её возраста 0.2 с. Optical-точка публикуется после выбора лица в общей системе координат;
преобразование по позе камеры от другого времени не используется.
Варианты CPU/стерео также подключены к [камере на руке](tracking_vision.md).

При потере лица, обрезанной/слишком маленькой рамке или плохой глубине **нет
новой 3D-точки**; состояние объясняет причину, зелёный маркер удаляется.
Маркеры также сами исчезают через 0.4 с без обновления. Старые координаты
не переиздаются. При полном прекращении входных кадров потребитель должен
проверять возраст последней точки: сами PointStamped не содержат флага потери.
Для реального оборудования используйте [аппаратные запуски](hardware.md).

## Границы модулей

Три небольших launch-файла выбирают режим; `face_depth_common.launch.py`
собирает камеры, мост, TF, обработчик и независимый оценщик.
`depth_geometry.py` содержит расчёты без ROS, `depth_backends.py` — OpenCV/ML,
`depth_node.py` — синхронизацию и ROS-выходы, `depth_reference.py` — сравнение.
Детекторы и 2D-контракт общие с отдельным тестом обнаружения лица.

Источники: [официальная метрическая реализация](https://github.com/DepthAnything/Depth-Anything-V2/tree/main/metric_depth),
[OpenCV StereoSGBM](https://docs.opencv.org/4.x/d2/d85/classcv_1_1StereoSGBM.html),
[ROS stereo_image_proc](https://docs.ros.org/en/ros2_packages/jazzy/api/stereo_image_proc/doc/components.html).
Глубина рассчитывается через OpenCV. Для камер этой сцены установка
`stereo_image_proc` не требуется. OpenCV — Apache-2.0;
лицензии детекторов и человека перечислены в инструкции 2D-теста.
