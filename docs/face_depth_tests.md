# Оценить 3D-точку лица

Эти тесты используют Gazebo Harmonic и ROS 2 Jazzy. Камеры неподвижны, рука не
запускается. Камеры имеют размер 640×480, частоту 30 кадров/с и стоят на высоте 1.65 м. Детектор находит
лицо, обработчик оценивает его положение в пространстве в метрах. Есть отдельные
варианты для CPU, стерео и нейросетевой глубины. Отдельный запуск подключается к
цветной камере и глубине, выровненной с RGB, от внешнего ROS-драйвера.

Для Gazebo сначала выполните [подготовку](face_detection_test.md#подготовка).
Запускайте только один тест за раз.

## Запуск

Подключите ROS 2 и установленный пакет:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
```

Запустите один вариант:

```bash
ros2 launch face_tracking_arm face_depth_cpu.launch.py
```

```bash
ros2 launch face_tracking_arm face_depth_stereo.launch.py
```

```bash
ros2 launch face_tracking_arm face_depth_gpu.launch.py
```

Для закрытия нажмите Ctrl+C. Gazebo показывает сцену, а RViz — кадр, рамки,
оценённую точку и эталон из Gazebo. Перемещайте в Gazebo человека. Не двигайте
камеры: их TF соответствует исходной позе.

GPU-тест требует отдельно подготовленных CUDA-зависимостей и весов. Он
экспериментальный; см. [подготовку GPU](#дополнительная-подготовка-gpu).

### Подключить внешний RGB-D источник

Этот запуск не стартует Gazebo или драйвер камеры. Он подписывается на RGB,
CameraInfo (параметры камеры) и aligned depth (глубину, выровненную с RGB)
из уже работающего источника:

```bash
ros2 launch face_tracking_arm face_depth_rgbd.launch.py \
  image_topic:=/camera/camera/color/image_raw \
  info_topic:=/camera/camera/color/camera_info \
  depth_topic:=/camera/camera/aligned_depth_to_color/image_raw \
  color_frame:=camera_color_optical_frame
```

Запустите драйвер отдельно и задайте его реальные имена топиков и optical frame.
RGB и глубина должны иметь одинаковые размеры, одинаковый optical frame и быть
выровнены. Их время съёмки должно быть близким. Основные аргументы этого запуска:

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| image_topic | /camera/camera/color/image_raw | RGB кадр |
| info_topic | /camera/camera/color/camera_info | Параметры RGB камеры |
| depth_topic | /camera/camera/aligned_depth_to_color/image_raw | Глубина, выровненная к RGB |
| color_frame | camera_color_optical_frame | Optical frame RGB |
| rgbd_sync_slop_sec | 0.02 с | Допустимая разница времени RGB и depth |
| max_frame_age_sec | 0.20 с | Максимальный возраст входной пары |
| source_timeout_sec | 0.25 с | Когда отметить остановку входного потока |

## Параметры запуска

Три Gazebo launch используют общие аргументы. Передайте их после имени файла.

| Аргумент | По умолчанию | Назначение |
|---|---:|---|
| detector | yunet | yunet, yolov5n_face или yolo_facev2n |
| headless | false | Запустить Gazebo без окон |
| show_image | true | Показать RViz |
| reference | true | Включить сравнение с глубиной Gazebo |
| threads | 2 | Потоки OpenCV и детектора |
| confidence | 0.6 | Минимальная уверенность детекции |
| face_width_m | 0.16 м | Принятая ширина лица для CPU |
| baseline | 0.08 м | База стереопары; допустимо 0.02–0.25 м |
| depth_input_size | 280 | Размер входа GPU-модели; кратен 14 и не меньше 140 |
| depth_scale | 1.0 | Ручной множитель GPU-глубины |

После имени аргумента и знака := не ставьте пробелы. Общие пути к модели и
окружению описаны в [подготовке 2D-теста](face_detection_test.md#подготовка).

## Как оценивается расстояние

### Одна RGB-камера: CPU

Обработчик оценивает оптическую глубину Z по ширине полностью видимой рамки:

`Z = fx × face_width_m / ширина_рамки_в_пикселях`.

Результат зависит от принятой физической ширины лица, поворота головы и точности
рамки. Это приблизительная оценка. Камера должна быть откалибрована. Частично
обрезанную рамку нельзя использовать для новой оценки ширины. Для того же лица
и свежей истории глубины CPU может кратко сохранить старый диапазон и обновить
направление. Возраст исходного измерения не обновляется. После смены лица старый
диапазон не применяется.

### Одна RGB-камера: GPU

GPU-вариант использует Depth Anything V2 Metric Hypersim Small. Модель
предсказывает глубину в метрах. Обработчик берёт медиану центральной области
лица. Модель рассчитана на внутренние сцены и обучена до 20 м. Выход обработчика
ограничен диапазоном 0.25–8 м.

В тестовой сцене ошибка достигала 1–2 м. Не используйте этот вариант для точной
дистанции без отдельной проверки. Нужна NVIDIA CUDA; автоматического перехода
на CPU нет. Больший depth_input_size не исправляет систематическую ошибку.

### Стерео: две RGB-камеры

OpenCV StereoSGBM оценивает сдвиг пикселей между синхронными изображениями.
Глубина рассчитывается по fx, базе стереопары и disparity (смещению пикселей).
Расчёт учитывает главные точки камер. База берётся из CameraInfo правой камеры. Аргумент baseline
задаёт её в Gazebo. Карта глубины Gazebo не используется.

При базе 0.08 м ближняя рабочая граница около 0.35–0.40 м. Дальность хуже
оценивается на гладких и удалённых поверхностях. Реальной стереопаре нужны
калибровка, выравнивание изображений и синхронизация. Стерео работает на CPU;
GPU используется только для графики Gazebo.

### Цвет и aligned depth: RGB-D

ROS RGB-D launch поддерживает 16UC1 в миллиметрах и 32FC1 в метрах.
Параметр rgbd_sync_slop_sec задаёт максимальную разницу меток времени RGB и
глубины; по умолчанию 0.02 с. Узел проверяет размеры, optical frame и свежесть
кадра. Несовместимая пара не даёт новой 3D-точки.

## Дополнительная подготовка GPU

Скрипт получает исходный код модели по закреплённой версии. По умолчанию он
не загружает веса. Чтобы явно запросить файл весом около 99 МБ, выполните из
корня проекта:

```bash
python3 scripts/prepare_metric_depth.py --download-weights
```

Скрипт проверяет SHA-256. Если существующий файл имеет другой хеш, он его
не перезаписывает. Веса сохраняются в
~/.cache/face_tracking_arm/models/. Исходный код и сведения о лицензии —
в ~/.cache/face_tracking_arm/depth_anything_metric/.

GPU launch использует совместимые CUDA-сборки PyTorch и torchvision в
perception_venv. Выберите их по версии NVIDIA-драйвера и CUDA через
[официальный установщик PyTorch](https://pytorch.org/get-started/locally/).
CPU- и stereo-тесты PyTorch не используют. Launch-файлы ничего не скачивают.

## ROS-контракт и свежесть данных

Основные выходы:

| Топик | Содержимое |
|---|---|
| /face_test/center_3d | geometry_msgs/PointStamped, точка лица в optical frame |
| /face_test/center_world | Та же точка в world в Gazebo, если есть TF на время кадра |
| /face_test/detections | Все рамки лица |
| /face_test/debug_image | Кадр с рамками и точкой |
| /face_test/depth_status | diagnostic_msgs/DiagnosticArray: причина, валидность точки, глубина и время обработки |
| /face_test/depth_estimate | Image, 32FC1 в метрах для GPU или stereo |
| /face_test/reference_3d | Независимая эталонная точка из Gazebo |
| /face_test/depth_error | Ошибка относительно эталонной точки |

Frame (система координат) камеры — face_test_camera_optical_frame: X вправо,
Y вниз, Z вперёд. Координаты заданы в метрах. Z — глубина вдоль optical Z; дальность по лучу
равна длине XYZ.

Для эталона Gazebo использует отдельное изображение глубины. Это сравнение
точки на поверхности лица по тому же лучу. Оно не проверяет анатомический центр
головы и недоступно в generic ROS RGB-D launch.

Связанные кадры и CameraInfo объединяются по точному времени. Frame проверяется
отдельно. Выход сохраняет время исходного кадра, включая точку в world.
Если TF на это время ещё не пришёл, узел ждёт до 0.2 с. Он не подставляет TF
из более позднего кадра.

Состояния /face/perception_status:

| Состояние | Значение |
|---|---|
| WAIT | Ещё нет пригодной пары кадров |
| OK | Есть пригодная измеренная точка |
| NO_FACE | Потоки исправны, лицо не найдено |
| FACE_NO_DEPTH | Лицо найдено, но глубина в нём непригодна |
| DEPTH_STREAM_LOST | Глубина отсутствует или непригодна |
| SYNC_ERROR, INVALID_INPUT, TF_UNAVAILABLE | Нельзя выдать пригодную точку |

При потере лица или глубины узел не публикует новую точку. PointStamped не
содержит флаг потери: потребитель должен проверять время последней точки.
Для RGB-D используйте диагностические топики /face_test/depth_status и
/face/perception_status.

### RGB-D и частичный проход у края

Aligned depth должна совпадать с RGB по размеру и optical frame. Метки времени
capture должны отличаться не более чем на rgbd_sync_slop_sec. Для глубины
16UC1 значение переводится из миллиметров; для 32FC1 — из метров. При
исправной паре без лиц состояние будет NO_FACE. Видимое лицо без подходящих
depth-пикселей даёт FACE_NO_DEPTH.

CPU не считает новую дальность по обрезанной рамке. Если тот же человек ещё
виден у края, обработчик может использовать предыдущую надёжную глубину до
0.30 с. Он обновляет направление, но не возраст исходного измерения. После
смены человека или истечения этого срока новую точку не выдаёт.

Для аппаратной RGB-D камеры см. [настройку оборудования](hardware.md). Лицензии
моделей и Gazebo-человека перечислены в [списке сторонних ресурсов](../THIRD_PARTY_NOTICES.md).

Алгоритмы: [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2),
[OpenCV StereoSGBM](https://docs.opencv.org/4.x/d2/d85/classcv_1_1StereoSGBM.html).
